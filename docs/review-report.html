Resolved during review

P1 · Pause/default-policy override

The earlier resume logic granted a fresh grace/window and could revive a boundary that had already expired. The fix replaced it with base_deadline + (total_paused_seconds - phase_pause_snapshot). Only completed real pause intervals accumulate; same-state calls add zero; reversed clocks and overflow fail closed.

Evidence: post-expiry, multiple-pause, snapshot, overflow, and state-transition tests now pass in the 16-test Rust suite.

Open production gates

High · Non-exhaustive transaction-level custody proof

The exact SBF artifact is deployed and a funded two-round devnet run exercised direct contributions, payouts, pre-grace rejection, post-grace collateral coverage, and terminal conservation. Crafted-account substitution, rollback, repeated-failure, and maximum-roster paths are not exhaustively tested. Fix: add Anchor/LiteSVM integration tests for every value path and malicious account substitution before production custody.

Medium · Authority governance incomplete

A dedicated repo-external devnet authority controls the deployed upgrade and pause surfaces; public program/config evidence exists, but multisig handoff remains open. Fix: publish the retained-authority assumption, transfer to reviewed multisigs, and rehearse pause/refund recovery before a production-value pilot.

Medium · AI operations remain pilot-grade

Economic records are decoded directly from confirmed devnet accounts and no static runtime catalog remains, but descriptive metadata is absent and the limiter is process-local. Fix: bind signed/versioned metadata to Group PDAs; add a durable distributed limiter, provider budgets, alerts, and key rotation before public paid-key traffic.

Low · Maximum-roster compute is unprofiled

The 32-member deterministic ordering path is bounded but O(N²). Fix: measure SBF compute/stack at the maximum roster and optimize or lower the cap only from measured results.
